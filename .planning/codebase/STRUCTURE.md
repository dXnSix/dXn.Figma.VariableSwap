## Directory Purposes

**Root Directory:**
- Purpose: Plugin source code and configuration
- Contains: TypeScript source, compiled output, build configuration
- Key files: `code.ts`, `manifest.json`, `package.json`

## Key File Locations

**Entry Points:**
- `code.ts`: Main plugin execution entry point, contains `main()` function called at module level
- `ui.html`: User interface entry point with button and postMessage listener
- `manifest.json`: Plugin registration metadata for Figma runtime

**Configuration:**
- `package.json`: NPM scripts, build tooling, dev dependencies, ESLint config
- `tsconfig.json`: TypeScript compiler options (ES6 target, strict mode)
- `manifest.json`: Plugin capabilities, document access level, UI reference

**Core Logic:**
- `code.ts` lines 4-31: `colorMapping` object with all variable name mappings
- `code.ts` lines 33-64: `getNodeVariables()` function for binding extraction
- `code.ts` lines 66-91: `findVariableByName()` function for variable resolution
- `code.ts` lines 110-195: `processNode()` function for recursive tree traversal and updates
- `code.ts` lines 93-107: `main()` orchestrator function

**Build Output:**
- `code.js`: Compiled JavaScript (generated by TypeScript compiler)
- `package-lock.json`: Locked dependency versions

## Naming Conventions

**Files:**
- Plugin code: lowercase with `.ts` extension (`code.ts`)
- Compiled output: same name with `.js` extension (`code.js`)
- Configuration: specific names expected by Figma (`manifest.json`, `ui.html`)
- Build config: standard names (`tsconfig.json`, `package.json`)

**Functions:**
- camelCase: `getNodeVariables()`, `findVariableByName()`, `processNode()`, `main()`
- Purpose-first naming with verb prefix: get/find/process pattern
- Async operations marked with `async` keyword

**Variables:**
- camelCase: `colorMapping`, `changesMade`, `localVariables`, `newVariable`
- Constants in object form: `colorMapping` is immutable mapping
- Loop variables: `collection`, `binding`, `variable` (descriptive names)

**Types:**
- Object mapping: `{ [key: string]: string }` for colorMapping
- Return types: `Promise<Variable | null>`, `Promise<number>`
- Tuple structure: `{ property: string; name: string }[]` for variable bindings

## Where to Add New Code

**New Variable Mappings:**
- Primary code: `code.ts` lines 4-31, `colorMapping` object
- Add entries following pattern: `"OLD_NAME": "NEW_NAME"`
- Comment with context: `// NEW_NAME - description`

**New Paint Properties:**
- Implementation: `code.ts` lines 154-183 (stroke handling as example)
- Pattern: Duplicate fills logic for new property type
- Check: Add condition in `processNode()` for property type checking

**New Variable Resolution Sources:**
- Implementation: `code.ts` lines 72-88 in `findVariableByName()`
- Add new search logic after library collection check
- Pattern: Try local first, then external sources, return null if not found

**Utilities/Helpers:**
- Shared helpers: Add at module level before `main()` in `code.ts`
- Pattern: Function declarations with `async` prefix for Figma API calls
- Keep utilities focused on single responsibility

## Special Directories

**node_modules/:**
- Purpose: NPM dependencies and TypeScript definitions
- Generated: Yes (created by `npm install`)
- Committed: No (listed in `.gitignore`)
- Contains: Build tooling (TypeScript, ESLint), type definitions (`@figma/plugin-typings`)

**.planning/:**
- Purpose: GSD planning documents (architecture, structure, conventions, concerns)
- Generated: Yes (created by GSD mapping process)
- Committed: Yes (for team reference)

## Build System

**TypeScript Compilation:**
- Command: `npm run build` compiles `code.ts` → `code.js`
- Watch mode: `npm run watch` for continuous compilation
- Output: `code.js` consumed by Figma plugin runtime

**Linting:**
- Command: `npm run lint` checks TypeScript files
- Fix mode: `npm run lint:fix` auto-fixes violations
- Config: Embedded in `package.json` eslintConfig section

## Import & Module Structure

**External Dependencies:**
- `@figma/plugin-typings`: Figma API type definitions imported via `/// <reference types="@figma/plugin-typings" />` at top of file
- No NPM imports in compiled code; types only

**Internal Organization:**
- Single-file structure: All code in `code.ts`
- No module imports between files
- Figma global API accessed directly: `figma.*`
